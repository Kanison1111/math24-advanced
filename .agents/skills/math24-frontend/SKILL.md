# Math 24 Frontend

## ขอบเขตการใช้งาน

ใช้ Skill นี้สำหรับงาน Frontend ของ repository `math24-advanced` อ่านคำสั่งของ repository และโค้ดที่เกี่ยวข้องก่อนทำงาน รักษาพฤติกรรมเดิม และเปลี่ยนเฉพาะส่วนที่จำเป็นต่อคำขอของผู้ใช้

## แนวทางการออกแบบ

1. ออกแบบแบบ Mobile-first เริ่มจากหน้าจอมือถือ แล้วปรับ layout ให้เหมาะกับแท็บเล็ตและคอมพิวเตอร์ ใช้พื้นที่หน้าจออย่างเหมาะสมทั้งแนวตั้งและแนวนอน
2. ใช้ธีมขาวดำ เรียบง่าย ทันสมัย กำหนดสี ระยะห่าง ตัวอักษร เส้นขอบ และรูปแบบปุ่มให้สม่ำเสมอ ใช้ลำดับความสำคัญของเนื้อหาแทนการตกแต่งที่รบกวนการเล่น
3. ปุ่มสัมผัสต้องกดสะดวก มีพื้นที่เป้าหมายประมาณ 44 × 44 CSS px ขึ้นไปและมีช่องว่างเหมาะสม ข้อความและสัญลักษณ์ต้องอ่านง่าย ไม่เกิด Horizontal Overflow ที่ความกว้างหน้าจอที่รองรับ รวมถึงเมื่อแสดงข้อความยาวหรือข้อความผิดพลาด
4. หน้าเกมให้ความสำคัญกับการ์ดตัวเลข สูตร และปุ่มตรวจคำตอบ แสดงเวลา คะแนน และความคืบหน้าอย่างกระชับ แยกปุ่มข้าม ล้าง และยุติออกจากการกระทำหลักอย่างชัดเจน รักษาความชัดเจนของเลขติดลบ เศษส่วน และเลขชี้กำลัง

## หน้าห้องและ Ranking

- หน้าสร้างห้อง: แสดงตัวเลือกและสรุปกติกาให้เข้าใจง่าย พร้อม validation และสถานะระหว่างสร้างห้อง
- หน้าเข้าร่วมห้อง: มีช่องรหัสห้องที่มี label รองรับคีย์บอร์ดและการวางข้อความ พร้อมข้อผิดพลาดกรณีรหัสไม่ถูกต้อง ห้องเต็ม หรือห้องไม่พร้อมใช้งาน
- ห้องรอแข่งขัน: แสดงรหัสห้อง รายชื่อผู้เล่น เจ้าของห้อง สถานะพร้อม กติกา และปุ่มเริ่มหรือออกจากห้อง อธิบายเหตุผลเมื่อยังเริ่มไม่ได้ รองรับสถานะหลุดและกำลังเชื่อมต่อใหม่
- Ranking: แสดงอันดับ ชื่อ และคะแนนอย่างอ่านง่ายทั้งมือถือและคอมพิวเตอร์ แสดงตัวกรองและเกณฑ์จัดอันดับตามระบบที่มีจริง พร้อมสถานะไม่มีข้อมูล กำลังโหลด และโหลดไม่สำเร็จ
- ออกแบบเฉพาะหน้าที่อยู่ในขอบเขตงาน ไม่สร้างระบบ Multiplayer, Supabase หรือ Ranking เพิ่มเองจากการเรียกใช้ Skill นี้ หากใช้ข้อมูลจำลองให้ระบุชัดเจนว่าเป็นข้อมูลตัวอย่าง

## Accessibility และสถานะการทำงาน

- ใช้ semantic HTML, label และชื่อที่โปรแกรมอ่านหน้าจอเข้าใจได้ ใช้ button สำหรับการกระทำและ link สำหรับการนำทาง
- รองรับ Keyboard Navigation, ลำดับ focus ที่เหมาะสม และ focus indicator ที่มองเห็นชัด หน้าต่าง dialog ต้องเปิด ปิด และคืน focus ได้ถูกต้อง ไม่ดักคีย์บอร์ดโดยไม่จำเป็น
- ใช้ contrast ที่อ่านง่าย ไม่สื่อความหมายด้วยสีเพียงอย่างเดียว ใช้ข้อความหรือสัญลักษณ์ร่วมด้วย และเคารพ prefers-reduced-motion
- เตรียม Loading States, Empty States, Disabled States และ Error States สำหรับงานที่เกี่ยวข้อง ป้องกันการส่งคำสั่งซ้ำระหว่างรอผล และแสดงวิธีลองใหม่เมื่อเหมาะสม
- แจ้งผลตรวจคำตอบและการเปลี่ยนแปลงสำคัญให้เทคโนโลยีช่วยเหลือรับรู้ เช่น ผ่าน aria-live โดยไม่ประกาศตัวจับเวลาถี่จนรบกวน

## ข้อจำกัดด้านโค้ดและแพลตฟอร์ม

- รักษาระบบคณิตศาสตร์ Parser, Solver, คลังโจทย์ คะแนน เวลา และกติกาเดิม ไม่แก้ไขโดยไม่จำเป็น หากพบปัญหาให้รายงานแยกจากงาน UI และเปลี่ยนเมื่ออยู่ในขอบเขตที่ผู้ใช้อนุญาตเท่านั้น
- ใช้ HTML, CSS และ JavaScript เดิมเป็นค่าเริ่มต้น แยกโมดูลหรือส่วนประกอบเมื่อช่วยให้อ่านและบำรุงรักษาง่าย ไม่เพิ่ม React, Next.js หรือ Framework ใหม่หากไม่มีความจำเป็นที่อธิบายได้
- เว็บไซต์ต้องทำงานบน GitHub Pages ได้ ใช้ static assets และเส้นทางที่รองรับการวางใต้ subpath ของ repository หลีกเลี่ยงการพึ่ง server-side rendering หรือ server routes สำหรับการโหลดหน้าเว็บ หากเพิ่ม client-side routing ต้องมีวิธีรองรับการเปิด URL โดยตรงบน GitHub Pages
- ห้ามใส่ secret หรือ Supabase service_role key ใน frontend หากงานต้องเชื่อม backend ให้แยกการเชื่อมต่อออกจาก UI และใช้สิทธิ์ที่เหมาะสม

## การตรวจสอบเมื่อปรับ UI

1. ตรวจบนเบราว์เซอร์ที่ขนาดมือถือและคอมพิวเตอร์จริงผ่านเครื่องมือที่มี อย่างน้อยประมาณ 360 px และ 1280 px และตรวจแนวนอนหรือความกว้างเพิ่มเติมตามส่วนที่เปลี่ยน
2. ตรวจว่าไม่มี Horizontal Overflow ตัวเลขและสูตรอ่านได้ ปุ่มไม่ทับกัน และคีย์บอร์ดบนมือถือไม่บังการทำงานสำคัญ ตรวจบนอุปกรณ์จริงเมื่อมีให้ใช้งาน และระบุข้อจำกัดหากตรวจได้เพียง viewport จำลอง
3. ทดสอบปุ่มและหน้าต่างที่เกี่ยวข้องทั้งการเปิด ปิด ยืนยัน ยกเลิก และการใช้คีย์บอร์ด รวมถึง loading/error states ที่เปลี่ยน
4. หากปรับหน้าเกม ให้ตรวจการป้อนสูตร ตรวจคำตอบ สุ่มโจทย์ คำใบ้ เฉลย และโหมดแข่งขันในส่วนที่ได้รับผลกระทบ เพื่อยืนยันว่าพฤติกรรมเดิมยังทำงาน
5. ตรวจเส้นทาง assets และการเปิดหน้าใต้ subpath แบบ GitHub Pages เมื่อมีการเปลี่ยนโครงสร้างหรือ navigation
6. สรุปสิ่งที่เปลี่ยน ขนาดหน้าจอและพฤติกรรมที่ทดสอบ พร้อมปัญหาหรือสิ่งที่ยังไม่ได้ทดสอบ อย่าอ้างว่าผ่านโดยไม่ได้ตรวจจริง
